# notebook

A notebook app with a web client (TanStack Start, which also serves the oRPC API and Better Auth) and a mobile client (Expo + Uniwind), sharing a Postgres/Drizzle backend. pnpm + Turborepo monorepo scaffolded with Better-T-Stack; `bts.jsonc` records the stack choices.

## How we work

- **Think first.** State your assumptions. When a request has more than one reading, lay them out and ask rather than picking silently.
- **Simplest thing that works.** Write the minimum code that solves the task: no speculative abstractions, options, or handling for cases that cannot happen.
- **Surgical diffs.** Every changed line traces to the request. Match the surrounding style. Mention unrelated problems you spot and leave them for a separate change.
- **Goal-driven.** Turn the task into a check you can run (a failing test, a type error, a request that returns the wrong thing), then loop until it passes.
- **Earn the complexity.** Existing code gets no free pass: if something is more complex than its job, say so and propose the simpler version.
- If a rule here fights the task in front of you, say so plainly and get my OK before breaking it.

## Toolchain

- Node 24, pinned in `.nvmrc`. Run `nvm use` first: Node 24.10 and older fail the stack's requirements.
- pnpm only. Dependency versions shared across packages live in the `catalog:` block of `pnpm-workspace.yaml`; packages reference them as `"catalog:"`.
- The root `package.json` scripts are the interface. Use them before calling tools directly.

## Done

A change is done when this passes:

```bash
pnpm check && pnpm check-types
```

For UI changes, also run the app and look at it. The web app runs at http://localhost:3001 (`pnpm dev:web`) and needs Postgres up (`pnpm db:start`). The web `check-types` includes a full Vite build, so expect it to take about 15 seconds.

## Gotchas

- Generated files, regenerated by command and never edited by hand:
  - `apps/web/src/routeTree.gen.ts`: rebuilt by the TanStack router plugin.
  - every `src/env.ts`: edit that package's `.env.schema`, then run `pnpm env:generate`.
  - `packages/db/src/schema/auth.ts`: change the Better Auth config, then run `pnpm auth:generate`.
- Real secrets live only in git-ignored `.env` files, and `.env.schema` holds only names and types. Add any new env var that a build reads to `globalEnv` in `turbo.json`, or Turbo will serve a stale cache.
- Ask me before running `pnpm db:push`, `pnpm db:migrate`, or anything that drops data.

## Git

Use Conventional Commits, scoped by workspace: `web`, `native`, `api`, `auth`, `db`, `ui`, `config`, or `deps` (example: `feat(api): add notes router`). Lefthook lints and formats staged files on commit and typechecks on push. When a hook fails, fix the cause and commit again.

Personal or machine-specific notes go in `CLAUDE.local.md`, which is git-ignored.
