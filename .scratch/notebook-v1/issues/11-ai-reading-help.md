# AI reading help

Type: grilling
Status: resolved
Blocked by: 10, 17

## Question

Given what "Calling Claude and ChatGPT through their CLIs" found, how does in-app AI generate reader content (summary, chapters for Sources without YouTube chapters, key points)? Q&A is handled by agents (see "Agent access: CLI, Claude Code skill, MCP"), not in the app. Settle:

- Claude or ChatGPT by default, and whether the Owner can pick per request.
- Generated automatically after transcription, or only on demand (each call spends plan usage and sends text off the machine).
- Where each item appears in the Article reader, and how chapter and key-point timestamps link.
- Storage and regeneration, including after the Owner edits the text.
- What the app shows when a CLI is logged out or over its limit.
- How AI output is labelled, so machine text is never mistaken for the Transcript.

## Answer

Decided with the Owner (grilling, 2026-11-22; recommendations accepted), building on "Calling Claude and ChatGPT through their CLIs". Q&A lives with agents ("Agent access: CLI, Claude Code skill, MCP"). In-app AI makes only **AI notes**.

1. **Provider:** Claude (`sonnet`) by default, with "Use ChatGPT instead" (`codex exec`, `gpt-6-luna`) as a per-request option.
2. **On demand only:** AI notes are generated when the Owner presses "Generate AI notes" on a Source, never automatically after transcription.
3. **Contents:** one structured call (JSON schema) returning:
   - a summary of 3–5 sentences;
   - 5–8 key points, each with a timestamp;
   - chapters with start times, only when the Source has no YouTube chapters.

   Very long Transcripts are split into parts and the notes merged.

4. **Reader:** a collapsible "AI notes" card above the Transcript holds the summary and key points; a key point's timestamp seeks there. Generated chapters join the Outline with an "AI" badge. All AI output carries "Generated by Claude/ChatGPT · date" in a distinct style, so it's never mistaken for the Transcript.
5. **Storage:** an `ai_notes` row per Source (provider, model, created_at, content JSON, and the Transcript revision it was made from). After Transcript edits, the card shows "Transcript edited since — regenerate?". Regenerating replaces the old notes.
6. **Failures:** before each call, check login without spending usage (`claude auth status --json`, never logged whole; `codex login status`). Show a specific message for each failure class:
   - logged out or expired: run `claude setup-token` on omarchy;
   - usage limit: try ChatGPT, or later;
   - timeout or changed CLI: retry, with a note that the CLI may have updated.
7. **Invocation:** the Bun server runs the research's isolated commands:
   - absolute binary paths (not mise wrappers), an empty working directory under `$XDG_RUNTIME_DIR/notebook-ai`, a minimal env;
   - a 120 s timeout, and one call at a time per provider;
   - `pnpm deploy:local` runs a flag smoke test after mise upgrades.

   If Claude's `-p` stops accepting subscription logins (the `--bare` default risk), ChatGPT is the fallback.

8. **Privacy:** before first use, the Owner turns off model training in Claude's privacy settings and ChatGPT's data controls. This is on the pre-use checklist.
9. **Export:** Markdown export gets an optional "AI notes (generated)" section, off by default and clearly labelled.
